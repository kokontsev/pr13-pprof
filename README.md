# Практическая работа 13

Профилирование и оптимизация Go.

Сравниваются рекурсивное и итеративное вычисление Fibonacci. Профилировщик действительно подключён к рабочему ServeMux через /debug/pprof/. Эндпоинт /work принимает n от 0 до 40 и fast=1. Сняты CPU-профили обеих версий и heap-профиль, выполнены три повтора каждого бенчмарка.

## Запуск на macOS или Linux

Go 1.27.1, curl. Каждая практика — отдельный Go-модуль. Команды выполняются из этой папки.

```bash
go test ./...
go vet ./...
go run ./cmd/api
# в другом терминале
curl "http://127.0.0.1:8080/work?n=38"
go tool pprof "http://127.0.0.1:8080/debug/pprof/profile?seconds=30"
go test -bench=. -benchmem ./internal/work
```

Файл `.env` читается оболочкой через `source`; автоматически сервер его не загружает. Порт API по умолчанию 8080. При одновременном запуске меняйте HTTP_ADDR, APP_ADDR (ПР9) или APP_PORT (ПР10).

## Подготовка к защите

Таймер измеряет длительность выбранного участка; CPU-профиль распределяет выборки по стекам. Профилирование помогает локализовать источник задержки.

flat — время непосредственно в функции, cum — время вместе с вложенными вызовами. Граф показывает цепочки и горячие узлы.

alloc_space считает суммарно выделенную память; inuse_space — оставшуюся занятой. Heap является выборочной оценкой.

Block и mutex профили включаются runtime.SetBlockProfileRate и SetMutexProfileFraction, затем собираются соответствующие pprof endpoints.

ns/op — время операции, B/op — выделенные байты, allocs/op — число аллокаций. Одинаковые входы и повторные замеры необходимы для сравнения.
